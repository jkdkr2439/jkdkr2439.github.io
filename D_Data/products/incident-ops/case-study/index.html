Dashboard ? Productivity

Overview

A local incident operations dashboard proving dense state, typographic severity, explicit ownership, causal timeline, composable filters, append-only audit, and deterministic recovery with failure preservation.

Behavioral model

Primary actors: on-call operator triaging under time pressure, incident commander coordinating recovery, engineering reviewer assessing evidence. Trust conditions: state visible before action, errors recoverable, ownership explicit.

Design decisions

Lenses: GOV.UK (service patterns), WCAG (accessibility), Nielsen (heuristics). Flow: orient ? discover modules ? enter destination ? return. Severity communicated through typographic weight + border, never color alone.

Architecture

apps/web/        ? semantic HTML shell + responsive CSS + modules
packages/domain/ ? incident-domain.js, filters.js, fixture.js (pure, no DOM)
infrastructure/  ? persistence/store.js (localStorage, swap to SQLite)
tests/           ? domain/ contract/ static/ (14 tests)

Quality evidence

  • Pipeline: ready_for_execution, 10/10 gates PASS, UCG 75 cards
  • Tests: 14/14 PASS
  • Browser: Chrome CDP 390px innerWidth=scrollWidth=390, no overflow
  • Recovery: deterministic fail ? context preserved ? retry ? monitoring ? explicit resolve
  • Keyboard: J/K navigate, Enter inspect, R recover, A audit, / search
